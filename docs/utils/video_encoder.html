utils::VideoEncoder

Writes RGBA8 frames to a video file by streaming them into an ffmpeg process. No GPU involved.

Role

The last step of graphics::Recorder, usable on its own with frames from anywhere. It runs 

ffmpeg -y -loglevel error -f rawvideo -pix_fmt rgba -s WxH -r FPS -i - \
       -c:v libx264 -preset slow -crf CRF -pix_fmt yuv420p -movflags +faststart PATH

and writes each frame to its stdin. H.264 in yuv420p plays everywhere; crf 16 is close to visually lossless (0 is lossless, higher is smaller and blurrier).

Public API

class VideoEncoder {
    struct Config { u32 width = 1920; u32 height = 1080; u32 fps = 60;
                    std::string path = "recording.mp4"; u32 crf = 16; };

    explicit VideoEncoder(Config);          // fatal if ffmpeg is missing or the size is odd
    ~VideoEncoder();                        // finish()
    void write(std::span<const u8> rgba);   // width * height RGBA8, row 0 at the top
    bool finish();                          // close stdin, wait for ffmpeg; false on error
    u64 framesWritten() const;
};

Worth knowing

  • ffmpeg is checked up front (command -v ffmpeg): a missing ffmpeg is RLOG(LL_FATAL) at construction, not a failure on the first frame.
  • Frames are 1/fps apart in the video regardless of how long they took to produce.
  • The path is single-quoted for the shell, so spaces are fine. The container comes from the extension.
  • Writing blocks while ffmpeg is busy; recording is offline, so a slow encode only makes recording take longer, never the video choppier.
