Display

utils::Display

A Rust-style trait, implemented as a C++20 concept: any type with a display() -> std::string method satisfies it.

Role

A structural contract for debug printing, checked at compile time. There's no base class to inherit and no registration step — a type opts in just by defining the method, and a static_assert next to the class turns "does this actually satisfy the concept" into a build-time guarantee rather than something discovered by trying to call it later.

Depends on / depended on by

Depends only on <concepts>/<string>. Implemented today by graphics::Light and scene::Scene, each with a static_assert(utils::Display<T>) right after the class definition.

Definition

template <typename T>
concept Display = requires(const T value) {
    { value.display() } -> std::same_as<std::string>;
};

Implementing it on a new class

class Thing {
    public:
        std::string display() const;
};

static_assert(utils::Display<Thing>);

That's the whole contract — one const method returning a std::string. Nothing else about the class needs to change, and nothing needs to know about Display to call .display() directly; the concept exists so generic code could require it (template <utils::Display T> ...), not because anything does yet.
