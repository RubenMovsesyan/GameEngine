graphics::primitives::scene::Frustum

Six bounding planes of a view volume, normals pointing inward — extracted from any world → clip matrix, used to reject geometry a pass can't see.

Role

A plain value type: six Eigen::Hyperplane<f32, 3> and the eight world-space corners of the volume. fromViewProjection() builds it from a combined view-projection matrix; intersects() answers "could this world-space AABB be visible?". It takes an arbitrary matrix rather than a Camera, so the same type serves the main camera today and shadow cascades / light volumes later — each of those is just a different world → clip matrix.

Depends on / depended on by

Depends only on Eigen (Dense + Geometry). Camera holds one, rebuilt in rebuildIfDirty() alongside the view/projection matrices. scene::Model::render() reads camera.frustum() once per model and calls intersects() per part to skip out-of-view StandardMesh draws.

Public API

class Frustum {
    enum class Plane { Left, Right, Bottom, Top, Near, Far };
    static constexpr usize kPlaneCount = 6;

    Frustum() = default;

    static Frustum fromViewProjection(const Eigen::Matrix4f& view_projection);

    bool intersects(const Eigen::AlignedBox3f& world_box) const;

    const Eigen::Hyperplane<f32, 3>& plane(Plane p) const;
    const std::array<Eigen::Vector3f, 8>& corners() const; // near {BL,BR,TL,TR} then far {BL,BR,TL,TR}
};

Worth knowing

  • Gribb–Hartmann extraction, rows not columns. Clip coordinates here are M · p (column-vector convention), so each clip-space inequality -w ≤ x ≤ w etc. is a linear combination of M's rows, not its columns. The w-row (M.row(3)) appears in every plane, so it's pulled out once: Left = row_w + row_x, Right = row_w - row_x, and so on. Get the convention backwards (use columns) and the planes come out transposed nonsense that still looks plausible for a symmetric frustum.
  • Near is row_z alone. Vulkan's clip volume is 0 ≤ z ≤ w, not OpenGL's -w ≤ z ≤ w. So the near plane is row_z by itself (from z ≥ 0), not row_w + row_z. Far is still row_w - row_z. This matches Camera's projection, which is derived for the [0,1] depth range directly.
  • Planes are normalized. Each plane's four coefficients are divided by the length of its xyz normal after extraction, so plane.signedDistance(point) is a true Euclidean distance — needed for any future "distance to plane ≥ -radius" sphere test (shadow-cascade fitting, light-volume culling). The normal points inward (positive distance = inside).
  • intersects() is the positive-vertex test, and it's conservative. For each plane it takes the single box corner farthest along that plane's inward normal (branchless: pick max or min per axis by the sign of the normal component). If even that corner is outside the plane, the whole box is outside → reject. It never returns false for a box that's actually visible, but a box straddling two planes near a frustum edge or corner can pass all six half-space tests and still be entirely outside the volume — it'll be drawn anyway. That's the accepted tradeoff for a six-compare test; the exact fix (also testing the frustum corners against the box) isn't worth it for culling.
  • Corners come from unprojecting the NDC cube. fromViewProjection() also inverts the matrix once and maps the eight NDC cube corners (x,y ∈ [-1,1], z ∈ [0,1]) back to world space, stored near-face first then far-face, each face ordered bottom-left, bottom-right, top-left, top-right. Unused by the main-camera cull path; it's there for cascade fitting.
