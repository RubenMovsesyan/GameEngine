assets::loaders::loadGltf

Parses a glTF/glb file with cgltf and returns a GltfAsset (models + lights). Registered as the GltfAsset loader by registerDefaultLoaders. The only place in the engine that knows cgltf exists.

Role

Parses the file, then walks each of the glTF scene's root nodes in turn — a glTF scene is a forest of independent root nodes (cgltf_scene.nodes[]), not one tree. Each root node's subtree is walked into its own working Model, accumulating world transforms and collecting mesh parts; any Light found anywhere in that subtree is appended to one flat list shared across the whole file, independent of which root node it was under. A root node whose subtree contains a mesh becomes one entry in the returned model list; a root node with no mesh anywhere under it (a light-only node, in every test asset today) ends up as an empty Model and is dropped rather than returned.

Depends on / depended on by

Depends on scene::Model, graphics::primitives::scene::StandardMesh/ Vertex/Light/ Material/ Texture, cgltf (vendored, single-header), and stb_image (vendored, single-header, image decode only, via decodeImage). Normally reached through AssetLibrary: load<GltfAsset> directly, or load<scene::Model> / load<std::vector<Light>> through the default split loader. graphics/ never depends on cgltf or stb_image.

Public API

// One Model per mesh-bearing scene root node; lights flat across the file.
struct GltfAsset {
    std::vector<scene::Model> models;
    std::vector<graphics::primitives::scene::Light> lights;
};

// Fatal on parse/buffer failure or unsupported content.
GltfAsset loadGltf(const std::filesystem::path& path);

// All root models' parts in one Model (copies share GPU buffers -- no re-upload).
scene::Model mergeModels(const std::vector<scene::Model>& models);

What it does and doesn't support

  • Triangle primitives only, indexed only — non-indexed or non-triangle primitives are a fatal error, not silently skipped.
  • Requires POSITION, NORMAL, and TEXCOORD_0 on every primitive.
  • Node transforms: cgltf_node_transform_local fills a column-major float[16], which matches Eigen::Matrix4f's default storage directly — Eigen::Map<const Eigen::Matrix4f>(local) reads it with no conversion.
  • Light direction/position come from the owning node's accumulated world transform, not from the light itself — glTF stores punctual lights as node attachments, same as meshes. Direction is local (0,0,-1) transformed by the inverse-transpose of the node's 3×3 linear block, so a non-uniformly scaled light node still points true — the same fix gbuffer.vert now uses for mesh normals (see normalMatrix()).
  • Each primitive gets a mesh-space AABB: if the POSITION accessor declares min/max (glTF requires it to, in practice), those two points are used directly; otherwise the vertex positions are scanned. It rides along into ModelPart::local_bounds for frustum culling.
  • Full metallic-roughness materials — loadMaterial() reads base_color_texture/metallic_roughness_texture plus base_color_factor/metallic_factor/roughness_factor off cgltf_pbr_metallic_roughness and builds a Material, called unconditionally per primitive (a primitive with no cgltf_material gets glTF's own defaults: both textures absent, factors (1,1,1,1)/1.0/1.0). occlusion_texture/normal_texture/emissive_* still aren't loaded — unrelated to what materials exist for right now (specular). No animation/skinning, no cameras/lights defined outside KHR_lights_punctual.
  • Texture bytes, combined or separate. resolveImageBytes() resolves a texture's raw compressed bytes three ways, always into one owned std::vector<u8> regardless of source (required so the bytes survive being moved into the background decode thread, past this function's own return): cgltf_image::buffer_view set → combined/embedded in the .glb, copied out of the buffer cgltf_load_buffers already loaded; uri starting with data:...base64, → decoded via cgltf's own cgltf_load_buffer_base64(), which needs the decoded size up front (unlike buffers, images don't carry a declared byte length in the glTF JSON) — computed from the base64 string length via the standard (len/4)*3 - padding formula; plain uri → a separate file, resolved against gltf_path.parent_path() after cgltf_decode_uri(), read with std::ifstream. sandbox/model_test/test_assets/smile_cube.gltf + smile_cube.bin + smile.jpg is the one asset in the repo exercising the separate-file path end to end. decodeImage() is the plain stb_image decode step, split out from byte resolution so loadGltfTexture() (base color, format SRGBA8_UNORM) and metallic_roughness_texture's load (format RGBA8_UNORM — it's linear data, not color) both reuse it unchanged.
  • Decode (stb_image) and GPU upload happen inside the callable handed to Texture::loadAsyncThread(), so they run on the detached background thread, not here — byte resolution above is the only synchronous part of texture loading in this function.
  • Fatal (not silently degraded) on: parse/buffer-load failure, no default scene, unsupported primitive/light type, missing required attributes, undecodable texture image — matches the engine-wide convention of RLOG(LL_FATAL, ...) for unrecoverable errors. The texture-decode fatal can fire from the background thread; a process-wide exit is fine from any thread.
  • mergeModels() concatenates every root model's parts into one Model for the default scene::Model split. Part copies share their GPU buffers and texture state, so nothing is re-uploaded.
  • Moved from src/scene/gltf_loader.* (where it returned scene::LoadedGltf) so every built-in loader lives under src/assets/loaders/.
