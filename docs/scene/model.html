scene::Model

A flat collection of meshes, each with its own local transform and material. Geometry only — no lights.

Role

Rendering a model means rendering each part individually: render() loops its parts and calls Renderer::renderMesh() once per part, combining the caller-supplied world transform with each part's local transform. No node hierarchy or scene graph — a flat list is all that's needed for what's actually loaded today. Each part can independently be a StandardMesh or an InstancedMesh — see Material Mesh.

Depends on / depended on by

Depends on graphics::Mesh (the concept, StandardMesh, InstancedMesh)/Renderer/Camera/ Material. Built by scene::loadGltf (one Model per glTF file, gathering every mesh primitive in the node tree, always as StandardMesh); owned by scene::Scene.

Public API

struct ModelPart {
    std::variant<graphics::StandardMesh, graphics::InstancedMesh> mesh;
    Eigen::Matrix4f transform; // local to the model's own origin
    graphics::Material material;

    void convertToStandard();    // shares buffers, no re-upload; warns and no-ops if already that kind
    void convertToInstanced();   // lossy for the reverse direction -- see graphics::Mesh
};

class Model {
    template <graphics::Mesh T>
    void addPart(T mesh, Eigen::Matrix4f transform, graphics::Material material);
    void render(graphics::Renderer&, const Eigen::Matrix4f& world_transform, const graphics::Camera&);

    u32 partCount() const;
    std::vector<ModelPart>& mutableParts();
};

Worth knowing

  • Meshes only, deliberately. An earlier version of this class also held Lights directly, which didn't make sense — a light illuminates a model, it isn't a kind of geometry. scene::Scene exists specifically to hold both Models and Lights together; Model went back to exactly this shape.
  • No static factory — unlike Mesh/Surface, Model doesn't allocate any GPU resource itself, it just aggregates already-created meshes, so ordinary construction + addPart() is enough.
  • addPart<T>() is templated, constrained by graphics::Mesh, and explicitly instantiated for StandardMesh/InstancedMesh in model.cpp — same pattern as Renderer::renderMesh<T>(). Keeps the real function body out of the header while still accepting either mesh kind at the call site; a third Mesh-satisfying type would need its own explicit instantiation line added.
  • render() is non-const, and iterates ModelPart& not const ModelPart& — it ultimately calls Renderer::renderMesh(T& mesh, ...), which needs mutable access so an InstancedMesh can upload its dirty instance buffer and clear the flag during render. This is why scene::Scene::render() is non-const too; StandardMesh pays the same non-const requirement for free even though it never actually mutates.
  • Dispatch to the right renderMesh<T>() instantiation happens via std::visit over ModelPart::mesh with a generic lambda — the compiler picks the right template instantiation per alternative, no manual type switch in Model::render().
  • material is always present and rides along, untouched by Model itself. addPart()'s trailing Material parameter has no default — building one needs a gpu::Device, so unlike the old std::optional<Texture> = std::nullopt shape, there's no device-free default to fall back to. scene::loadGltf is the only caller and always builds a real one via loadMaterial(), including for a primitive with no glTF material at all (defaults, both textures absent). Whatever the Material holds just gets forwarded into Renderer::renderMesh() during render() — optionality (a texture present or not, still background-loading or not) lives entirely inside Material/Texture now, one level down from Model.
  • No CPU-side vertex/index retention. convertToStandard()/ convertToInstanced() reuse the existing GPU buffers rather than rebuilding from original geometry (which ModelPart doesn't keep a copy of) — see StandardMesh::fromInstanced()/InstancedMesh::fromStandard(). Converting instanced → standard therefore drops the per-instance transform list; there's no way to recover it afterward.
