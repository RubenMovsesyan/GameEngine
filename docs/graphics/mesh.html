graphics::Mesh

A C++20 concept, not a class: anything with a vertex buffer, an index buffer, and an instance count. StandardMesh and InstancedMesh are the two things that satisfy it.

Role

Mesh used to be one concrete class. It became a concept so Renderer::renderMesh() and scene::Model could work with either a single non-instanced mesh or a mesh drawn many times with per-instance transforms, without an inheritance hierarchy or a runtime type tag — std::same_as-checked structural requirements instead, verified at compile time via static_assert(Mesh<StandardMesh>)/static_assert(Mesh<InstancedMesh>) right below each class (same pattern as Display).

Depends on / depended on by

Both concrete types depend on gpu::Device. StandardMesh is built by scene::loadGltf (one per glTF primitive); either type can end up inside a scene::ModelPart via scene::ModelPart::convertToStandard()/ convertToInstanced(). Drawn by the templated graphics::Renderer::renderMesh<T>(), explicitly instantiated for both types.

Public API

struct Vertex {
    Eigen::Vector3f position;
    Eigen::Vector3f normal;
    Eigen::Vector2f uv;
};

template <typename T>
concept Mesh = requires(const T& value) {
    { value.vertexBuffer() } -> std::same_as<nvrhi::IBuffer*>;
    { value.indexBuffer() } -> std::same_as<nvrhi::IBuffer*>;
    { value.indexCount() } -> std::same_as<u32>;
    { value.instanceCount() } -> std::same_as<u32>;
};

class StandardMesh {
    static StandardMesh create(const gpu::Device&, std::span<const Vertex> vertices, std::span<const u32> indices);
    static StandardMesh fromInstanced(const InstancedMesh&);   // shares buffers, drops instance data

    nvrhi::IBuffer* vertexBuffer() const;
    nvrhi::IBuffer* indexBuffer() const;
    u32 indexCount() const;
    u32 instanceCount() const;   // always 1
};

class InstancedMesh {
    static InstancedMesh create(const gpu::Device&, std::span<const Vertex> vertices, std::span<const u32> indices);
    static InstancedMesh fromStandard(const StandardMesh&);    // shares buffers, starts with 0 instances

    nvrhi::IBuffer* vertexBuffer() const;
    nvrhi::IBuffer* indexBuffer() const;
    u32 indexCount() const;
    u32 instanceCount() const;

    u32 addInstance(const Eigen::Matrix4f& transform);
    void removeInstance(u32 index);
    Eigen::Matrix4f* mutableInstance(u32 index);

    nvrhi::IBuffer* instanceBuffer() const;
    void uploadIfDirty(const gpu::Device&);
};

Worth knowing

  • Private constructor + static factory on both classes — matches every GPU-resource class in this engine (Surface does the same); protects the invariant that a mesh always has real, uploaded buffers. This is also why the concept only requires accessors, never a constructor: construction is deliberately not part of the shared interface.
  • instanceCount() always returns at least 1 — a non-instanced draw is just an instanced draw with one instance. This matches nvrhi::DrawArguments::instanceCount's own default of 1, so Renderer::renderMesh() can call .setInstanceCount(mesh.instanceCount()) unconditionally for either type without a branch.
  • fromInstanced()/fromStandard() reuse the source's GPU buffers instead of re-uploading vertex/index data — they only copy the nvrhi::BufferHandles (which is why they take a const& to the other type and only call its public accessors, no friend declarations needed). Converting InstancedMesh → StandardMesh is lossy: the per-instance transform list is simply not carried over. Nothing here reads GPU memory back to CPU, so there's no way to recover it after the fact — this only works because scene::ModelPart::convertToStandard()/convertToInstanced() is the only caller, and it treats the loss as expected.
  • Dirty-flag upload, not automatic sync. addInstance()/ removeInstance()/mutableInstance() only touch the CPU-side std::vector<Eigen::Matrix4f> and set a dirty flag; uploadIfDirty() is what actually rebuilds instanceBuffer() from scratch (no partial updates) and clears the flag. mutableInstance() marks dirty unconditionally on every call, same reasoning as Camera's mutablePosition(): the class can't know whether the caller actually wrote a different value through the returned pointer.
  • uploadIfDirty() can't run while a frame's command list is open. gpu::Device::createBuffer() opens its own immediate command list internally: the same "two immediate command lists open at once" class of bug this engine hit before with LightManager's lazy build. Renderer::renderMesh<T>() calls uploadIfDirty() automatically every frame (so future per-frame instance edits stay in sync), but the first upload — right after populating instances, before the render loop's first beginFrame() — has to happen explicitly by the caller, same as LightManager::build(). See Renderer's notes on the instanced pipeline for the full story.
