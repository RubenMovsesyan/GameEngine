graphics::Camera

View + projection matrices, Vulkan-convention, hand-derived (no glm/GLU dependency).

Role

A look-at camera: position, target, a fixed world-up of (0,1,0), and a perspective projection built directly from FOV/aspect/near/far. No scene-graph attachment, no controller logic — mutablePosition()/setLookAt() exist so calling code (e.g. an orbit camera in a test harness) can drive it directly.

Depends on / depended on by

Depends only on Eigen. graphics::Renderer::renderMesh() reads viewProjectionMatrix()/position() every call; scene::Model/scene::Scene::render() just forward a const Camera& through.

Public API

class Camera {
    Camera(f32 fov_y_radians, f32 aspect_ratio, f32 near_plane, f32 far_plane,
           const Eigen::Vector3f& position, const Eigen::Vector3f& target, const Eigen::Vector3f& up);

    Eigen::Matrix4f transformationMatrix() const;              // world -> camera space
    Eigen::Matrix4f viewProjectionMatrix() const;               // projection * transformationMatrix()
    Eigen::Vector3f position() const;

    Eigen::Vector3f* mutablePosition();                         // for driving it in place
    void setLookAt(const Eigen::Vector3f& target);
};

Worth knowing

  • Projection has no Y-flip (m_projection(1,1) = f, not -f). Vulkan clip space is Y-down by default, and the textbook advice for porting an OpenGL-style projection to Vulkan is to negate that term — but this pipeline's view matrix already produces the correct on-screen orientation without one. Adding the textbook flip mirrors the image (confirmed empirically: it also inverted every mesh's apparent winding, i.e. rendered everything inside out). If you ever "fix" an upside-down render by flipping this sign back, you must also flip graphics::Renderer's gbuffer RasterState.frontCounterClockwise to match, or culling breaks instead. The two settings are a matched pair, not independent — a Y-flip mirrors the transform, which necessarily inverts screen-space winding parity too.
  • Depth range is Vulkan's [0,1], not OpenGL's [-1,1] — the row-2 near/far terms are derived for that directly, not adapted from a GL formula.
  • transformationMatrix() is a standard right-handed look-at (right = forward × up, up' = right × forward), camera looking down -Z in view space — matches glTF's own camera convention, which matters since scene::loadGltf loads content authored under that convention.
