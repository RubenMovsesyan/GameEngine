graphics::Recorder

A Presenter that also records: every frame goes to the window and into a video file, a fixed 1/fps apart however long it took to render.

Role

Drop-in for Presenter::present while recording. Any Renderer can be recorded unchanged — the Recorder only sees the image render() returns. Each frame:

  1. renders at the video's size (Config::width × height), not the window's;
  2. a compute pass (capture_cs in engine.glsl) packs the image into a storage buffer as RGBA8, one uint per pixel, row 0 at the top — any source format, clamped to 0..1;
  3. an internal Presenter shows the image in the window (scaled), draws the overlay on top, and commits the frame;
  4. gpu::BufferReadback copies the storage buffer to the CPU, a few frames behind so the GPU never waits;
  5. utils::VideoEncoder streams the frames into ffmpeg.

The overlay (ImGui, an FPS counter, ...) is drawn on the window only: the capture happens before the blit, so the video holds just the renderer's image.

Fixed timestep

Frames are 1/fps apart in the video no matter how long they take, so drive the simulation from frameTime() instead of the wall clock while recording. Then the video plays back in real time even when rendering is far slower than that — you can record at settings too slow to run live. 

graphics::Recorder recorder{{.width = 1920, .height = 1080, .fps = 60, .path = "out.mp4"}};

// per frame
simulate(recorder.frameTime());     // not the wall clock
recorder.present(renderer, overlay);
if (done) {
    recorder.finish();              // encodes the frames still in flight, closes the file
    app.quit();
}

Public API

class Recorder {
    struct Config { u32 width = 1920; u32 height = 1080; u32 fps = 60;
                    std::string path = "recording.mp4"; u32 crf = 16; };

    explicit Recorder(Config);       // fatal if ffmpeg is missing or readback is unavailable
    ~Recorder();                     // finish()

    template <Renderer R>
    void present(R& renderer, const std::function<void()>& overlay = {});

    f64 frameTime() const;           // 1 / fps
    u64 framesPresented() const;     // frames recorded so far
    void finish();                   // flush + close; later frames are shown but not recorded
    bool finished() const;
    const Config& config() const;
};

Worth knowing

  • Vulkan only, through gpu::BufferReadback; ffmpeg must be installed (checked when the Recorder is built — fatal if missing).
  • No CUDA. The readback is plain Vulkan on sokol's queue.
  • It renders once per frame at the video size and shows that same image, rather than rendering twice. A renderer that rebuilds targets on a size change won't thrash.
  • Three frames are in flight; present() only waits on the GPU if the CPU (encoding) falls three frames behind.
  • Width and height must be even (H.264 with 4:2:0 chroma).
  • sandbox/recorder_test records a known sequence of colours (./run recorder_test --out x.mp4); decode it to check frame count and order.
