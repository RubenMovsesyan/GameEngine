GameEngine

A C++23/Vulkan game engine built on NVRHI, structured as five layers with a strict one-way dependency chain. This page explains how they relate; each class has its own page in the sidebar with real signatures and design decisions.

The layers

gpu/
Device primitives only: instance, physical/logical device, swapchain, buffer/texture loans via NVRHI. Never includes GLFW, never knows a window exists.
graphics/
Rendering mechanism: the Mesh concept (StandardMesh/InstancedMesh), Material, Texture (sync or background-thread loaded), Light, LightManager, Surface, the deferred Renderer, PostProcessChain. "How to draw," with no asset-format knowledge (no cgltf, no stb_image).
scene/
Composition: Model (a collection of meshes) and Scene (Models + Lights). The glTF loader lives here too — cgltf is an implementation detail of this layer alone.
app/
Runtime shell: Application (owns window/device/swapchain/workers/input), Window (GLFW, cursor capture), InputState (thread-safe keyboard/mouse), Worker/WorkerBase, CliParser.
utils/
Cross-cutting, dependency-free helpers — currently just the Display concept.

Dependency direction is one-way down this list: app depends on scene depends on graphics depends on gpu. Nothing lower ever includes something higher — e.g. graphics/ never includes cgltf.h, that stays inside scene/gltf_loader.cpp alone.

One frame, end to end

app::Application owns a worker thread running graphics::Renderer's own loop: beginFrame() → renderMesh() per mesh (geometry/G-buffer pass) → endFrame() (lighting pass into an HDR target, then PostProcessChain narrows that to the swapchain). See Renderer for the full pass breakdown and a diagram.

Build system

No CMake. build.cpp is a C++ program using buildcpp (a git submodule) to describe the build directly — one binary, sandbox/model_test, no separate static libraries per module. Shaders are compiled to SPIR-V at build time (glslc -mfmt=c) and embedded as C headers, so the binary carries its own bytecode with no runtime shader loading. 

./build -j $(nproc)   # or just: ./run

Conventions worth knowing before editing

ConventionWhy
Every module is a plain directory under src/, headers next to sources, no separate include/.Matches this repo's flat layout; the include root is just src.
GPU resource classes (Mesh, Surface) use a private constructor + static factory.They allocate real GPU resources with an invariant to protect; plain data types (Light, ModelPart) don't need this.
New post-process effects: write a .frag, add it to build.cpp's shader list, addPass() it.Compile-time extension only — no runtime shader loading exists.
A class that wants debug printing implements std::string display() const and static_assert(utils::Display<T>).See Display.
