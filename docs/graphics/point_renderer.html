graphics::renderers::PointRenderer

A second implementation of the Renderer concept: self-luminous points, nothing lit. The first dependency of the galaxy simulator (roadmap 1a), landed as wiring only.

Role

Draws a set of emissive points — stars, sparks, particles. There is no G-buffer, no lighting pass and no shadows: every point emits and nothing is lit. Each point is expanded into a camera-facing billboard, the billboards are additively blended (ONE/ONE) into an HDR target, and that target is tonemapped to an LDR RenderTarget whose view render() returns for the Presenter to blit. Additive blending is order-independent, so there is no depth buffer and no sort.

Input: PointInstance

graphics::primitives::scene::PointInstance (point.hpp) is plain data — no GPU ownership — fixed at 32 bytes so a std::span of them maps straight onto a per-instance vertex buffer: 

struct PointInstance {
    Eigen::Vector3f position;  // world space
    f32             size;      // world-space radius of the billboard
    Eigen::Vector4f color;     // linear radiance (may exceed 1); .a is an intensity multiplier
};

submit(std::span<const PointInstance>) copies the span into the renderer’s own instance buffer. It is shaped for this renderer the way DeferredRenderer::submit is shaped for meshes — the Renderer concept only fixes render(), so a per-renderer submit() is a convention, not part of the concept.

Public API

  • beginFrame(const Camera&) — stashes the view and projection used to expand the billboards (uses Camera::projectionMatrix(), added for this renderer). Call once per frame before submit()/render().
  • submit(std::span<const PointInstance>) — the frame’s points.
  • setExposure(f32) — multiplier before the ACES tonemap curve; default 1.
  • sg_view render(int width, int height) — records the additive point pass and the tonemap pass, returns the final LDR view. Does not call sg_commit().

The points shader

One program in engine.glsl. The vertex stage builds a two-triangle quad from gl_VertexIndex, expands it by inst_size in view space (so it always faces the camera) and offsets it by inst_position. The fragment stage applies a soft round falloff and emits color.rgb * color.a * falloff for the additive blend to accumulate.

Deliberately still stubbed

This is wiring only. Tracked in roadmap/galaxy-simulation.md and not built yet:

  • bloom (a star is a clamped 1–2 px dot without it), in shared post so the deferred renderer can use it too;
  • auto-exposure / exposure recalibration for a near-black frame;
  • a blackbody colour ramp (temperature → RGB);
  • a streaming instance buffer — submit() recreates the buffer every frame today;
  • spatial-cell culling.

Depends on / depended on by

Depends on RenderTarget, TonemapPass, Camera, and PointInstance (point.hpp). Driven by the application layer and handed to a Presenter — see sandbox/point_test/point_test.cpp (./run point_test).
