assets::AssetLibrary

Load a file once, share it everywhere. A cache of loaded assets of any type, keyed by (type, canonical path), with loaders registered per type at runtime.

Role

Before this, every sandbox called its loader directly and kept the result in its own variables; drawing a model twice meant loading the file twice. Now load<T>(path) returns a shared pointer to the one cached instance, and a second call with the same path (in any spelling — ./cube.glb, /abs/dir/../cube.glb) returns that same pointer. 

assets::AssetLibrary assets;
assets::loaders::registerDefaultLoaders(assets);

auto cube   = assets.load<scene::Model>("res/cube.glb");                // parses the glb
auto again  = assets.load<scene::Model>("res/cube.glb");                // same pointer
auto lights = assets.load<std::vector<Light>>("res/cube.glb");         // cache hit, no re-parse
auto tex    = assets.load<Texture>("res/smile.jpg");

// A custom asset type: register a loader once, then load<T> works for it.
assets.setLoader<Heightmap>([](const std::filesystem::path& p) { return Heightmap::fromFile(p); });

Depends on / depended on by

Header-only templates over the standard library plus rlog; knows no asset type itself. Built-in loaders live in src/assets/loaders/ and are registered by registerDefaultLoaders(). Used by sandbox/model_test.

Public API

class AssetLibrary {
    public:
        template <typename T>
        using Loader = std::function<T(const std::filesystem::path&)>;

        AssetLibrary() = default;
        // Split producers capture `this`: pinned in place.
        AssetLibrary(const AssetLibrary&) = delete;
        AssetLibrary& operator=(const AssetLibrary&) = delete;

        // Replaces any earlier loader for T. Receives the canonical absolute path.
        template <typename T>
        void setLoader(Loader<T> loader);

        // split(const Source&) -> std::tuple<Ts...>; a direct setLoader<Ti> takes precedence.
        template <typename Source, typename... Ts, typename Fn>
        void setSplitLoader(Fn&& split);

        // Shared, read-only. Fatal if no loader can produce T or the file doesn't exist.
        template <typename T>
        std::shared_ptr<const T> load(const std::filesystem::path& path) {
            return loadShared<T>(path);
        }

        // Same cached object as load<T>(), mutable: edits are visible to every holder.
        template <typename T>
        std::shared_ptr<T> loadMut(const std::filesystem::path& path) {
            return loadShared<T>(path);
        }

        template <typename T>
        bool contains(const std::filesystem::path& path) const {
            return m_cache.contains(Key{typeid(T), canonical(path)});
        }

        usize size() const { return m_cache.size(); }
        // Drops the library's references; objects die once callers drop theirs too.
        void clear() { m_cache.clear(); }

        static std::string canonical(const std::filesystem::path& path);
};

Split loaders

One file can hold several kinds of asset (a glTF has models and lights). setSplitLoader<Source, T1, ..., Tn>(split) declares that each Ti comes from a Source already loadable at the same path. load<Ti>(path) loads (or reuses) the Source, calls split(const Source&) once, and caches every tuple element under (Ti, path). You choose which sub-assets exist by what the split returns; a "many of a kind" product is a container type, e.g. std::vector<Light>. 

assets.setSplitLoader<GltfAsset, scene::Model, std::vector<Light>>(
    [](const GltfAsset& g) { return std::tuple<scene::Model, std::vector<Light>>{mergeModels(g.models), g.lights}; });

Worth knowing

  • Key = (C++ type, canonical path). The path is made absolute and normalized with std::filesystem::weakly_canonical. Keying by type as well lets one path hold several assets (the glTF source, its Model, its lights).
  • load vs loadMut: both return the same cached object. loadMut just drops the const, so an edit is visible to every holder, including load callers.
  • Failure is fatal: no loader for the type, or a missing file, ends the process via RLOG(LL_FATAL) with the demangled type name. Loaders themselves follow the same convention.
  • Runtime registration (std::function per type) means a missing loader is caught at the load call, not at compile time. In exchange, a sandbox can replace a built-in loader with its own.
  • Precedence: a direct setLoader<T> beats a split loader that also produces T. The split source stays cached after splitting. A product already in the cache (e.g. from a direct loader) is not overwritten by a later split.
  • Lifetime. clear() drops only the library's references; any shared_ptr a caller still holds keeps its object alive. Most assets own sokol handles, so call clear() and drop your own pointers before sg_shutdown() (see model_test's cleanup()).
  • Not movable or copyable: split producers capture this.
  • Frame thread only. Loaders create sokol resources and the cache is unsynchronized. Texture decoding still happens off-thread inside the texture loader (Texture::loadAsyncThread).
  • Shared Model means shared Model::world_transform. Place copies from the caller side (as model_test's submitModel(..., placement, ...) does), not by editing the cached model.
