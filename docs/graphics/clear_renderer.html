graphics::renderers::ClearRenderer

The smallest implementation of the Renderer concept: one pass that clears a target to a solid colour. For bring-up, and as the template for a new renderer.

Role

Proves the whole path from window to screen is wired — app::Application brings up sokol, the renderer records a pass into its own RenderTarget, and the Presenter blits that to the swapchain and commits — without any pipeline, shader or scene input. When a solid colour shows up, everything below a real renderer works.

Public API

  • explicit ClearRenderer(sg_color color = {0, 0, 0, 1}) — RGBA in [0, 1], written as-is into an RGBA8 target.
  • setColor(sg_color) — change the colour; takes effect next frame.
  • sg_view render(int width, int height) — records the clear pass, returns the target’s view. Does not call sg_commit().

The whole of render()

The target is rebuilt only when the size changes. The pass clears and ends — no draw calls — and the cleared image is the frame: 

sg_pass pass = {};
pass.action.colors[0].load_action = SG_LOADACTION_CLEAR;
pass.action.colors[0].clear_value = m_color;
pass.attachments.colors[0] = *m_target.attachment;
pass.label = "clear pass";
sg_begin_pass(&pass);
sg_end_pass();

return *m_target.texture;

Usage

std::optional<graphics::renderers::ClearRenderer> renderer;
std::optional<graphics::Presenter> presenter;

app::Application app(
    {.title = "yellow"},
    [&](app::Application&) {
        renderer.emplace(sg_color{1.0f, 1.0f, 0.0f, 1.0f});
        presenter.emplace();
    },
    [&](app::Application&) { presenter->present(*renderer); },
    [&](app::Application&) { presenter.reset(); renderer.reset(); });
app.run();

Both are std::optional because they own GPU handles: they can only be built once sg_setup() has run (inside init) and must be released before sg_shutdown() (inside cleanup).

Depends on / depended on by

Depends on RenderTarget only. Used by ElectronCloud as its first-light test.
