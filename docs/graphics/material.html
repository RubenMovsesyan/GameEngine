graphics::Material

glTF's metallic-roughness material model: two optional textures plus the scalar factors that always apply.

Role

Carries what the geometry pass needs to write real per-surface metallic/roughness into the G-buffer's material channel, instead of the flat placeholder it used to write. Mirrors what cgltf_pbr_metallic_roughness actually defines: base_color_texture/metallic_roughness_texture are genuinely optional (same optionality Texture loading already had for base color), base_color_factor/metallic_factor/roughness_factor are always meaningful (default (1,1,1,1)/1.0/1.0 regardless of whether a texture exists).

Depends on / depended on by

Depends on gpu::Device and Texture. Built by scene::loadGltf's loadMaterial() (one per glTF primitive, unconditionally — a primitive with no cgltf_material still gets a Material, just one with both textures absent and every factor at its glTF default). Held on scene::ModelPart::material; read every frame by Renderer::renderMesh() for the G-buffer pass's texture and factors-buffer bindings.

Public API

class Material {
    static Material create(const gpu::Device&, std::optional<Texture> base_color_texture,
                            std::optional<Texture> metallic_roughness_texture,
                            const Eigen::Vector4f& base_color_factor, f32 metallic_factor, f32 roughness_factor);

    const std::optional<Texture>& baseColorTexture() const;
    const std::optional<Texture>& metallicRoughnessTexture() const;
    nvrhi::IBuffer* factorsBuffer() const;

    // Cached G-buffer texture/sampler/factors binding set; rebuilt only on texture-handle change.
    nvrhi::IBindingSet* gbufferBindingSet(nvrhi::IDevice*, nvrhi::IBindingLayout*,
                                           nvrhi::ITexture* white_fallback, nvrhi::ISampler*) const;
};

Worth knowing

  • First draft of this design baked the factors into synthesized pixels; that was wrong. The obvious first move was: make metallic_roughness a required, always-real Texture, synthesizing a solid 1×1 color to carry the factors when glTF has no texture. That breaks the symmetry glTF itself defines — metallic_roughness_texture is optional, exactly like base_color_texture already was — and forces every texture-less material through a GPU upload for what's really just two floats. Corrected to keep the texture genuinely optional and carry the factors as an actual tiny buffer instead.
  • The factors live in a real GPU buffer, not a push constant. GBufferPushConstants (renderer.cpp) is already 2×mat4 = 128 bytes — exactly Vulkan's spec-guaranteed minimum maxPushConstantsSize, which some real desktop hardware (AMD in particular) provides and no more. There's no safe headroom to grow it. Instead, create() builds a tiny read-only structured buffer (same shape LightManager::build() already uses for the light array — one struct instead of an array) holding {base_color_factor, metallic_factor, roughness_factor}, bound at a new StructuredBuffer_SRV slot.
  • Factors are multiplied in-shader, after sampling — not baked into texture pixels at load time. This matters for base_color_factor specifically: base_color_texture's format is SRGBA8_UNORM, so the GPU sRGB-decodes it on sample; the stored bytes are gamma-encoded, and base_color_factor is a linear-space multiplier. Multiplying the raw stored bytes before upload would be gamma-wrong. Multiplying after texture() in gbuffer.frag operates on the already-decoded linear value, so it's correct with zero extra work.
  • "No texture" and "no metalness/roughness" are different things, and Material keeps them separate. When metallic_roughness_texture is absent, Renderer binds its shared m_white_texture fallback (same one base_color_texture already falls back to) — sampling white reads (1,1,1,1), so sampled.g * roughness_factor == roughness_factor exactly, matching glTF's own spec: the implicit sample when no texture exists is 1.0. The actual value for a texture-less material lives entirely in the factor, in the buffer — the texture slot never needs to lie about it.
  • The G-buffer binding set is cached on the Material, not rebuilt per draw. renderMesh() used to call device->createBindingSet() every draw call. Now gbufferBindingSet() builds it once and returns the cached nvrhi::BindingSetHandle on every later call. The cache key is just the two resolved nvrhi::ITexture* pointers (base color, metallic-roughness, each falling back to Renderer's shared white texture when absent): a raw pointer compare, which catches both the first build and the one handle change that actually happens — Texture swapping its placeholder for the real image once the background decode finishes. The sampler, layout, and white fallback are all Renderer-owned and stable for the process, so they're passed in rather than stored and aren't part of the key.
  • Private constructor + static factory, matching every other GPU-resource class here (Texture, Mesh, Surface) — protects the invariant that m_factors_buffer is always built.
