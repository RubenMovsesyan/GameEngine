graphics::Texture

A GPU-resident 2D texture. Can load synchronously from already-decoded pixels, or asynchronously on a detached background thread while a fuchsia/black checkerboard placeholder stands in.

Role

Wraps one nvrhi::TextureHandle the same way Material Mesh wraps vertex/index buffers. Its second job — background loading — exists because glTF texture decode (stb_image) plus GPU upload was stalling the whole scene load; loadAsyncThread() returns instantly with a placeholder and swaps in the real texture once a detached thread finishes decoding and uploading it.

Depends on / depended on by

Depends on gpu::Device (createTexture(), guarded internally by Device's own submit mutex — see Device). Built by scene::loadGltf for each primitive's base-color texture; held on scene::ModelPart::texture; read every frame by graphics::Renderer::renderMesh() for the G-buffer pass's albedo binding.

Public API

struct DecodedPixels {
    std::vector<u8> pixels; // tightly packed RGBA8
    u32 width = 0;
    u32 height = 0;
};

class Texture {
    static Texture create(const gpu::Device&, std::span<const u8> pixels, u32 width, u32 height,
                           nvrhi::Format format = nvrhi::Format::RGBA8_UNORM);
    static Texture createPlaceholder(const gpu::Device&); // 2x2 fuchsia/black checkerboard, synchronous

    static Texture loadAsyncThread(const gpu::Device&, std::function<DecodedPixels()> decode,
                                    nvrhi::Format format = nvrhi::Format::RGBA8_UNORM);

    nvrhi::ITexture* texture() const;
    u32 width() const;
    u32 height() const;
    bool isReady() const; // false while still showing the placeholder
};

Worth knowing

  • The mutex can't be a direct Texture data member. ModelPart::texture is a std::optional<Texture> living inside std::vector<ModelPart> — the vector needs its elements movable (e.g. on growth), and std::shared_mutex is neither copyable nor movable. Worse, a detached background thread can't safely hold a raw Texture*/this either, since the wrapper object itself can be relocated (vector reallocation, optional moves) while the thread is still running, dangling the pointer. Fix: the mutex and mutable state live in a private heap-allocated State struct, and Texture is just a thin std::shared_ptr<State> handle — cheap to copy/move, and a background thread captures the shared_ptr by value, keeping State alive for as long as it needs regardless of what happens to any Texture copy.
  • loadAsyncThread() stays decode-agnostic. The caller supplies a std::function<DecodedPixels()> that turns raw compressed bytes into pixels — graphics/ never touches stb_image directly, matching the existing rule that asset-format knowledge stays in scene/. scene::loadGltf is the only caller today and supplies the stb_image call.
  • createPlaceholder() reuses create() internally, then forces ready back to false. create() always marks its result ready (it's a real, complete texture by construction) — the placeholder needs to say the opposite (this is a stand-in, not the requested texture), so createPlaceholder() overrides the flag after building it rather than duplicating the upload logic.
  • Known, accepted gap from choosing "detach" over "join": a background load thread captures &device by reference and keeps running after loadAsyncThread() returns. If app::Application tears down gpu::Device while a load is still in flight, that's a use-after-free — Application::~Application() only joins its tracked Workers, not stray detached threads. Not fixed (no thread-registry/join-on-shutdown mechanism exists); a real gap this design choice creates, not an oversight.
  • Row pitch for uploads is computed via nvrhi::getFormatInfo(format).bytesPerBlock (the same call NVRHI's own Vulkan backend uses internally) rather than hardcoding 4 bytes/pixel.
