gpu::BufferReadback

Copies sokol storage buffers back to the CPU — something sokol_gfx can't do on any backend.

Role

A small ring of slots. Each slot is a sokol storage buffer the GPU writes this frame (in any pass — graphics::Recorder fills it with a compute pass) plus a CPU-readable copy of it. With N slots the CPU reads frame k while the GPU works on frames k+1 .. k+N−1, so nothing waits unless the CPU falls behind. 

// per frame, on the sokol thread
sg_buffer target = readback.acquire(onReady);   // encodes the oldest frame first if the ring is full
/* write `target` in a pass */
sg_commit();                                    // (the Presenter does this)
readback.submit();                              // queue the copy behind the frame

// at the end
readback.flush(onReady);                        // onReady(std::span<const u8>) per frame, in order

How the copy works (Vulkan)

  • An engine-owned command pool on sokol's queue family, one command buffer + fence per slot, and a host-visible, host-coherent (cached if available) VkBuffer per slot, mapped once.
  • submit() records barrier (shader write → transfer read), vkCmdCopyBuffer, barrier (transfer write → host read) and submits it on sokol's queue after sg_commit(). A pipeline barrier's first scope covers everything earlier in submission order on the queue, so it orders the copy after sokol's frame without touching sokol's command buffer — the same trick gpu::CrossSemaphore uses for its empty submits.
  • Reading waits on the slot's fence, hands the mapped bytes to the callback, and frees the slot. A slot is only reused after its copy has been read, so the GPU can't overwrite a frame the CPU hasn't seen.

Worth knowing

  • Vulkan only. create() returns nullopt elsewhere. A Metal version would be a shared-storage buffer read in place.
  • Needs one sokol fork change: storage buffers are created with VK_BUFFER_USAGE_TRANSFER_SRC_BIT (in _sg_vk_buffer_usage, fenced GameEngine fork); upstream sokol only gives buffers TRANSFER_DST. The source buffer is found with the fork's sg_vk_query_buffer_info.
  • The storage buffers are immutable — sokol's rule for buffers bound read/write.
  • Not thread-safe: everything happens on the sokol thread, like the rest of sokol.
