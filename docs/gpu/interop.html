gpu — zero-copy CUDA ↔ Vulkan buffer sharing

A CUDA compute thread integrates a GPU buffer in place, on its own clock, while the render thread draws the same bytes — no copy, no CPU in the loop. Built for the galaxy sim; see sandbox/cuda_points_test (./run cuda_points_test).

Why a sokol fork

Upstream floooh/sokol's Vulkan backend exposes no VkBuffer accessor and no way to make a buffer's memory exportable. external/sokol is a fork (branch gameengine/vk-interop, every hunk marked GameEngine fork) that adds the minimum:

  • sg_buffer_desc.vk_external_memory — that buffer gets a dedicated, exportable (OPAQUE_FD) VkDeviceMemory.
  • sg_vk_query_buffer_info() / sg_vk_query_device_info() — the VkBuffer/VkDeviceMemory and the VkInstance/PhysicalDevice/Device/Queue sokol holds.
  • sokol_app.h: request VK_KHR_external_memory_fd + VK_KHR_external_semaphore_fd, enable the timelineSemaphore feature.

It deliberately does not touch sokol's per-frame vkQueueSubmit. Sync is done with empty vkQueueSubmits that bracket sokol's submit on the same queue. Pivot away from the fork once upstream sokol grows first-class external-memory support.

The pieces

ExternalBuffer
external_buffer.*		 An sg_buffer with exportable dedicated memory, plus the opaque FD (from vkGetMemoryFdKHR) and the allocation size CUDA needs.
CrossSemaphore
cross_semaphore.*		 An exportable Vulkan timeline semaphore. queueWait/ queueSignal are empty submits on sokol's graphics queue; the FD is imported by CUDA. Timeline = monotonic u64, no signal-before-wait hazard.
CudaInterop
cuda_interop.*		 CUDA Driver API (no nvcc, no libcudart): match the device by UUID to sokol's VkPhysicalDevice, retain the primary context, cuImportExternalMemory → a mapped CUdeviceptr that aliases the exact drawn bytes, cuImportExternalSemaphore. All #ifdef GAMEENGINE_CUDA.
SharedInstanceBuffer
shared_instance_buffer.*		 The orchestrator. consumeBegin/End on the render thread; attachCuda + (produceBegin/End or publishIfRequested) on the one CUDA worker. Three sync modes below — the mode is the priority policy.

Sync modes

Sync::Semaphore (default) — render-priority

One buffer, strict alternation via two timeline semaphores. The compute thread waits render_done (buffer free), runs as many integration sub-steps as it wants, then signals sim_ready; the render thread waits sim_ready at VERTEX_INPUT, draws, then signals render_done after sg_commit. Sim rate can far exceed the frame rate (sub-steps per hand-off); minimal latency; no extra VRAM.

Sync::DoubleBuffer

Two buffers. The compute thread integrates freely into the back buffer, syncs its stream, and flips it to the front once the last frame that read it has retired (render_done ≥ flip_frame). The render thread always draws the current front. Compute is fully unthrottled; ~1 frame more latency; 2× VRAM. Only render_done is used.

Sync::SimPriority — sim-priority

The compute thread owns a private authoritative buffer (cuMemAlloc, never drawn) and hammers it in place with no render-gated wait, ever. When the render thread wants a fresh frame it sets an atomic; the next sim iteration’s publishIfRequested() copies the private buffer into a free slot of a 3-buffer ring (on the sim stream, race-free with the kernels) and bumps the publish_done timeline value. The render thread draws the newest ready slot, waiting only on that copy — never on the sim. A render stall just drops snapshots (the ring-slot check in publishIfRequested is a non-blocking vkGetSemaphoreCounterValue); the sim rate holds. ~3× VRAM (ring only). The sim kernels run on a high-priority CUDA stream (CudaInterop::makeStream(true)).

Build & threading notes

  • CUDA is optional. build.cpp probes CUDA_PATH then /opt/cuda; when found it defines GAMEENGINE_CUDA, links libcuda, and adds the sandbox. The sandbox kernel is nvcc --ptx'd and cuModuleLoaded at runtime, keeping nvcc out of the C++ link.
  • The compute thread is an app::Worker (app.addWorker). A worker may drive CUDA but must never call sg_*. Application starts it after init() and, on shutdown, sets workerShouldStop() then joins it before the cleanup callback — so the worker's own detachCuda() (which releases the CUDA context + imports that alias Vulkan memory) runs while sokol/Vulkan are still up. Only then is the rest of the Vulkan state torn down.
