graphics::Renderer & graphics::renderers::DeferredRenderer

A one-method concept that any renderer satisfies, and the deferred renderer that is the first implementation of it.

The concept

graphics::Renderer (src/graphics/renderer.hpp) is the entire contract between a renderer and the Presenter: 

template <typename T>
concept Renderer = requires(T& renderer, int width, int height) {
    { renderer.render(width, height) } -> std::same_as<sg_view>;
};

A renderer, given a target size, records every GPU pass for one frame and returns a texture view of the finished, presentable image. It owns everything else — its render targets, pipelines, tonemap, post, debug overlays, resize handling. A deferred renderer, an emissive point renderer for a starfield, a compute raymarcher: all are just different implementations of this one concept, and the Presenter never reaches inside any of them. Two rules the concept itself cannot express but every implementation must honour:

  • render() must not call sg_commit() — the Presenter owns the frame boundary.
  • the returned sg_view must stay valid until the next render() call.

DeferredRenderer — the deferred implementation

Deferred shading: a directional cascaded shadow pass, then one G-buffer pass with a draw per submitted mesh, then fullscreen lighting, sky, tonemap and FXAA passes. Its output is left in an LDR RenderTarget for the Presenter to blit. It owns every pipeline and target involved.

Depends on / depended on by

Depends on RenderTarget, FullscreenPass, TonemapPass/FxaaPass, Mesh, Material, Camera, LightManager, Skybox, DebugDraw, and graphics::computeCascades (shadow.hpp). Driven by the application layer and handed to a Presenter — see sandbox/model_test/main.cpp.

Public API

class DeferredRenderer {
    DeferredRenderer();

    void beginFrame(const Camera&);        // stash view/VP, mark cascades for a refit

    template <Mesh T>
    void submit(T& mesh, const Material&, const Eigen::Matrix4f& model,
                const Eigen::AlignedBox3f& world_bounds, bool camera_visible);

    void setLights(const LightManager&);   // call between beginFrame() and render()
    void setSkybox(const Skybox&);
    void setExposure(f32);
    void setAmbient(const Eigen::Vector3f&);
    void setFxaaEnabled(bool);
    void setShadowDistance(f32);
    void setCascadeSplitLambda(f32);

    // shadow-map debug blit controls
    void toggleShadowMapDebug();
    void cycleShadowMapDebugLayer();
    bool isShadowMapDebugEnabled() const;
    void setShadowMapDebugEnabled(bool);
    u32  shadowMapDebugLayer() const;
    void setShadowMapDebugLayer(u32);

    DebugDraw& debugDraw();

    // Records shadow -> G-buffer -> lighting -> sky -> tonemap -> FXAA at width x height
    // and returns a view of the final LDR image. Does not commit. (the concept's render())
    sg_view render(int width, int height);
};

static_assert(Renderer<DeferredRenderer>);

One frame

Worth knowing

  • The window size is an argument, not a reach-around. render(width, height) (re)builds the screen-sized targets on the first call and whenever the size changes; the renderer never calls sapp_width()/sapp_height() itself. Simulation time never enters the renderer at all — it renders exactly what was submitted.
  • Cascades are fitted in render(), not beginFrame(). The fit needs the sun direction, which setLights() supplies, and setLights() is called after beginFrame() by contract. beginFrame() just stashes the camera; render() reads it back once setLights() has had its turn.
  • Two LDR targets, to avoid read-after-write. Tonemap writes m_tonemapped (both it and the final m_ldr are RGBA8; the HDR lighting/sky buffer m_hdr is RGBA16F); FXAA reads m_tonemapped and writes m_ldr; the shadow-map debug blit and the DebugDraw line overlay also draw into m_ldr; render() returns m_ldr.texture. FXAA no longer targets the swapchain — the Presenter does that blit, and composites the app's ImGui overlay on top of it.
  • All five fullscreen passes go through FullscreenPass (tonemap and FXAA via TonemapPass/FxaaPass). The shader programs, formats, bindings and pass order are unchanged from the pre-plugin renderer — only the C++ wrapping moved.
  • submit() has no notion of "camera". The caller decides per mesh whether it is camera-visible (typically Camera::frustum() intersect its world bounds); camera_visible == false still records the mesh into the shadow pass (an off-screen object casts a shadow into view) but skips it in the G-buffer pass.
  • Ambient is a flat per-frame uniform (default (300, 300, 300)), a stand-in for sky bounce until image-based lighting exists — scaled to survive the ~0.003 tonemap exposure and meant to be tuned alongside the Skybox intensity.
