graphics::Renderer

A deferred renderer driving its own swapchain-present loop, meant to run off a worker thread.

Role

Per frame: a geometry (G-buffer) pass per mesh, one full-screen lighting pass, a full-screen sky pass that fills the pixels no geometry covered, then a post-process chain that narrows HDR down to the display. Owns every GPU pipeline/texture involved; callers only ever call the handful of methods below.

Depends on / depended on by

Depends on gpu::Device/gpu::Swapchain, and on Mesh, Material, Texture, Skybox, Camera, LightManager, PostProcessChain, Surface. Driven directly by whatever code owns the render loop (currently sandbox/model_test/main.cpp, via a worker thread started by app::Application).

Public API

class Renderer {
    Renderer(const gpu::Device&, gpu::Swapchain&);

    void beginFrame();

    template <Mesh T>
    void renderMesh(T& mesh, const Material& material, const Eigen::Matrix4f& model, const Camera&);

    void setLights(const LightManager&);   // call between beginFrame() and endFrame()
    void setSkybox(const Skybox&);         // gradient colours + intensity for the sky pass
    void setExposure(f32);                 // brightness multiplier before the tonemap curve
    void setAmbient(const Eigen::Vector3f&); // flat ambient irradiance added to every lit surface
    void setFxaaEnabled(bool);             // FXAA post-pass; on by default
    void endFrame();
};

One frame

Worth knowing

  • The sky is a dedicated full-screen pass, not a branch in lighting.frag. It runs in endFrame() right after the lighting draw, into the same m_hdr_color target, reading only the G-buffer depth: sky.frag does if (depth < 1.0) discard; so it only touches the far-plane pixels the lighting pass left as background. Its push constants carry the reconstructed view ray inputs (inverse_view_projection, view_position — same values the lighting pass already computed), the gradient's zenith/ground colours + intensity, and a kind selector (0 = gradient, 1 = cubemap, stubbed). Keeping it separate means a future cubemap adds a samplerCube to m_sky_binding_layout alone — the 6-slot lighting layout and lighting.frag are untouched. See Skybox.
  • Ambient is a per-frame uniform now, not a shader constant. lighting.frag used to add a hard-coded kAmbient = 0.1; it now reads pc.ambient.rgb from the lighting push constants, set via setAmbient() (default (300, 300, 300)). It's a flat stand-in for sky bounce until IBL exists — scaled to that magnitude for the same ~0.003 exposure reason the Skybox intensity is, and meant to be tuned together with it.
  • FXAA is the second registered PostProcessChain pass (fxaa.frag, after tonemap.frag), on by default. setFxaaEnabled(false) doesn't remove the pass — the shader still runs but takes a pc.enabled < 0.5 passthrough branch, so toggling it costs nothing structural. Its push constants (reciprocal frame size + the enable flag) are re-seeded on every rebuildPostProcessTargets() because the frame size changes on resize.
  • Every post pass after tonemap.frag has to cancel the NVRHI viewport Y-flip by hand. The Vulkan viewport is Y-flipped for every draw; the first post pass (tonemap) samples with that flip and so un-flips the HDR target, but each later pass would re-flip it. fxaa.frag samples with vec2(vUv.x, 1.0 - vUv.y) to compensate — any new pass added after the first one needs the same inversion.
  • Lighting no longer writes the swapchain directly. It writes an RGBA16_FLOAT offscreen target (m_hdr_color) so light values can exceed 1.0 without hard-clipping — real Blender-exported intensities are physically large (see Light), and an 8-bit LDR target clips anything over 1.0 straight to white. PostProcessChain's last pass is what actually narrows HDR to the display.
  • Point-light shading needs per-fragment world position, which the lighting pass doesn't have directly. Rather than adding a 4th G-buffer target for it, the lighting shader reconstructs it from the existing depth buffer: sample depth, build NDC, multiply by the inverse view-projection matrix, divide by w. That matrix comes straight from Camera's own cache (inverseViewProjectionMatrix()) — Renderer doesn't compute any matrix inverse itself. This keeps the geometry pass writing exactly what it always did.
  • NDC.y is negated in reconstructWorldPosition (lighting.frag): -(uv.y * 2.0 - 1.0), not the plain uv.y * 2.0 - 1.0 every other NDC component uses. NVRHI's Vulkan backend flips Y at the viewport level for every draw (VKViewportWithDXCoords in vulkan-graphics.cpp, the standard negative-height viewport trick), completely separate from anything the projection matrix does. Rasterizing and sampling the G-buffer both go through that same viewport convention automatically, so they stay self-consistent without anyone thinking about it — but reconstructWorldPosition is pure math bypassing the viewport entirely, so it has to undo that flip by hand. Symptom when this was missing: point-light shading on a perfectly static object visibly shifted as the camera moved vertically (light appeared to move opposite the camera on Y only, since the viewport's flip is Y-only) — a real bug, not a hypothetical one.
  • renderMesh()/setLights() stash camera/light state for endFrame() to read later — correct only when called once per frame with one camera, which is the only way this engine calls them today.
  • NVRHI's Vulkan backend offsets sampler bindings by 128 by default; every binding layout here zeroes it explicitly (VulkanBindingOffsets().setSamplerOffset(0)) so shader source can use plain binding = N numbers.
  • gbuffer_state.rasterState.setFrontCounterClockwise(true) matches Camera's projection having no Y-flip — see Camera's note on why these two settings are a matched pair.
  • Backface culling is on by default — gbuffer_state only sets frontCounterClockwise; RasterState::cullMode is never touched, so it stays at NVRHI's own default of RasterCullMode::Back. Both G-buffer pipelines share gbuffer_state, so this applies equally to instanced and non-instanced draws. It's the rasterizer's screen-space winding-order test, not a per-triangle dot(normal, view_dir) check in the shader — same visibility result for a closed mesh, done before rasterization instead of in the fragment shader.
  • Two G-buffer pipelines, chosen per call via if constexpr. renderMesh<T>() checks requires { mesh.instanceBuffer(); } — true only for InstancedMesh — to pick between m_gbuffer_pipeline/gbuffer.vert (one vertex buffer, slot 0) and m_gbuffer_instanced_pipeline/gbuffer_instanced.vert (adds two per-instance mat4s at buffer slot 1, isInstanced = true, stride sizeof(InstanceData): INSTANCE_TRANSFORM and INSTANCE_NORMAL_MATRIX, each setArraySize(4) on an RGBA32_FLOAT attribute, which NVRHI's Vulkan backend expands into locations 3–6 and 7–10 right after position/normal/uv). The shader multiplies pc.model * inInstanceTransform for the world matrix and mat3(pc.normal_matrix) * mat3(inInstanceNormalMatrix) for the normal basis (the normal matrix of a product is the product of the normal matrices). Detecting the mesh kind via a requires-expression rather than checking a concrete type name means a third Mesh-satisfying type with its own instanceBuffer() would automatically take the instanced path too.
  • The first instance-buffer upload must happen before the render loop starts. renderMesh<T>() calls mesh.uploadIfDirty() automatically (via the same if constexpr (requires {...}) trick) so future per-frame instance edits stay synced — but gpu::Device::createBuffer() opens its own immediate command list, and that can't happen while Renderer's own command list is already open between beginFrame()/endFrame() (the same "two immediate command lists open at once" crash this engine hit before with LightManager's lazy build). Concretely: sandbox/model_test/main.cpp populates a grid of instances right after loading, then calls uploadIfDirty() once, explicitly, before entering the frame loop — mirroring LightManager::build()'s explicit, once, outside-any-frame pattern. Skipping that call and letting the first upload happen inside the first renderMesh() reproduces the crash.
  • The G-buffer's per-draw binding set carries a whole Material now, sampled in gbuffer.frag. renderMesh<T>() takes a const Material& and builds one nvrhi::BindingSetHandle per call from m_gbuffer_texture_binding_layout: Texture_SRV(0) base color, Texture_SRV(1) metallic-roughness, Sampler(2) one shared m_gbuffer_sampler for both (no per-texture wrap/filter settings from the glTF sampler yet), StructuredBuffer_SRV(3) the material's factors buffer. Either texture slot falls back to m_white_texture (a 1×1 white pixel built once in the constructor) when a Material's texture is absent — same "a null handle isn't valid there" reasoning as m_empty_light_buffer, and correct per spec: sampling white reads 1.0, so the shader's factor multiply alone produces the right value. This set is no longer rebuilt per draw: renderMesh() asks the Material for it via gbufferBindingSet(), which caches it and only rebuilds when a texture handle actually changes (the async placeholder → real swap). The lighting and sky passes' own sets are cached the same way, as m_lighting_binding_set/m_sky_binding_set members rebuilt only on resize — and m_lighting_binding_set also on setLights(), but only when the incoming light buffer is a different handle than last frame's (that buffer is the one moving resource in the set).
  • m_material went from declared-but-dead to a real G-buffer target. It existed from the start of texture support but was never attached to m_gbuffer_framebuffer or written by gbuffer.frag. Wiring it in touched three spots: gbuffer_fb_info gained a third addColorFormat(RGBA8_UNORM), rebuildGBuffer()'s framebuffer gained a third addColorAttachment(m_material), and beginFrame()'s per-frame clears gained a third call — all three had to move together, or the framebuffer/format counts stop matching what the pipeline was created with.
  • Lighting reads m_material at a new Texture_SRV(5) and shades Cook-Torrance GGX instead of Lambertian-only — packed as G = roughness, B = metallic (R reserved for occlusion later, unused). No new push constant needed: view_position was already uploaded every frame from camera.position(), sitting unused since the HDR/point-light work, comment said "reserved for specular" from the start. The diffuse term picked up the 1/π Lambertian normalization it didn't have before (needed for energy-consistency with the new specular term), which makes diffuse ~3.14× dimmer at the same light intensity — kDefaultExposure moved from 0.001f to 0.003f to compensate. See Material for what's actually in the G/B channels.
  • Descriptor set index is assigned by addBindingLayout() call order, not declaration order in the shader. GLSL bindings with no explicit set= qualifier (all shaders in this engine) default to set 0. The G-buffer pipelines originally added the push-constant layout first and the texture/sampler layout second, putting push constants at set 0 — the validation layer immediately flagged tAlbedo/sLinear as "not declared in pSetLayouts[0]". Fixed by adding m_gbuffer_texture_binding_layout first (matching the lighting pass, which already got this order right: m_lighting_binding_layout before m_lighting_push_constant_layout) — and state.bindings's element order in renderMesh() has to match: texture binding set first, push-constant binding set second.
  • The world normal is octahedral-encoded into an RG16_FLOAT target. The G-buffer normal attachment used to be RGBA32_FLOAT (16 bytes/pixel storing a unit vector plus a dead .w). gbuffer.frag now calls octEncode() — fold the unit sphere onto an octahedron, unwrap to a 2-channel [-1,1] square — and lighting.frag does the inverse octDecode() on read. Half the bandwidth for that attachment, and a deferred renderer is bandwidth-bound on the G-buffer. The encode/decode helpers are inlined in both shaders (no shared .glsl include mechanism here); if a third pass ever needs the normal it copies octDecode() too.
  • view_projection is a per-frame constant buffer, not part of the G-buffer push constant. GBufferPushConstants is {model, normal_matrix} — two mat4s, exactly the 128-byte guaranteed push-constant minimum, no room for a third. So the camera's view_projection moved to m_camera_buffer, a constant buffer at set = 1, binding = 1 in the vertex stage, written once per frame on the first renderMesh() call (it's identical for every mesh that frame). NVRHI's Vulkan backend offsets constant-buffer registers by 256 by default; the binding layout zeroes that so the GLSL binding = 1 matches, the same way every layout here zeroes the 128 sampler offset. The buffer is isVolatile with maxVersions = kFramesInFlight + 2: NVRHI auto-versions each writeBuffer so an in-flight frame keeps reading the version it was recorded with.
  • Point lights outside their range skip the BRDF entirely. lighting.frag's point branch does if (range > 0.0 && dist >= range) continue; before any Cook-Torrance math — pointAttenuation() is already 0 past the range, so the shading was wasted work. A finite range is per-light in position_range.w; range == 0 still means infinite.
  • Frames in flight, paced by an event-query ring instead of vkDeviceWaitIdle. endFrame() used to drain the whole GPU after every submit — zero CPU/GPU overlap. Now kFramesInFlight = 2 nvrhi::EventQueryHandles (m_frame_done) form a ring: endFrame() resets and sets slot frame_counter % kFramesInFlight on the graphics queue after submit; beginFrame() waits on that slot's query only once frame_counter ≥ kFramesInFlight, i.e. only when the CPU is a full two frames ahead. NVRHI recycles its own command-list buffers and emits the cross-submit barriers, so the single command list and single G-buffer don't need N-buffering — only the volatile camera buffer does (above). The acquire semaphore is still per-swapchain-image; the constructor asserts imageCount > kFramesInFlight so a semaphore can't be re-waited while its submit is still pending. The resize and present-failure paths deliberately keep a full vkDeviceWaitIdle — they're rare and need every prior frame done before textures are recreated.
