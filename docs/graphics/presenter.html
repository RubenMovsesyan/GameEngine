graphics::Presenter

Takes whatever a Renderer produced this frame and puts it on screen — nothing more.

Role

The whole "graphics engine" side of the frame loop that is not a renderer. present() drains pending texture uploads, asks the renderer for this frame's finished image at the current window size, opens the swapchain pass, blits that image across it with the present shader (a plain copy — no tonemap, no gamma), runs the app's overlay callback on top inside the same pass, and commits. Swap the renderer for a different implementation of the Renderer concept and this class does not change.

Depends on / depended on by

Depends on the Renderer concept (its present is constrained by it), on FullscreenPass for the blit, on Texture for drainUploads(), and on sokol_app/sokol_glue for the window size and swapchain. Constructed and driven by the application layer — see sandbox/model_test/main.cpp, which calls presenter.present(renderer, overlayLambda) once per frame.

Public API

class Presenter {
    Presenter();

    template <Renderer R>
    void present(R& renderer, const std::function<void()>& overlay = {});
};

Worth knowing

  • It owns the frame boundary. Texture::drainUploads(), sglue_swapchain() and sg_commit() are called here and nowhere else. A renderer's render() must not commit; if you ever run a renderer without a Presenter you have to drain uploads yourself.
  • One extra fullscreen blit per frame. The renderer writes an LDR target and the Presenter copies it to the swapchain, rather than the renderer writing the swapchain directly. That is the price of decoupling: the renderer never needs to know the swapchain exists, and the overlay (ImGui) composites cleanly on top.
  • present() is a template so the concept can constrain it, but the non-template guts (beginFrame, blitAndFinish, the size accessors) live in presenter.cpp — so the generated engine.glsl.h stays out of the header and out of every translation unit that merely includes presenter.hpp.
  • Rule of zero: m_sampler is a handle that frees itself; the blit pipeline is a raw sg_pipeline left to sg_shutdown(), the same as the deferred renderer's pipelines. The sandbox still resets the Presenter before the renderer and both before the GPU tears down.
