graphics::primitives::pass::TonemapPass / graphics::primitives::pass::FxaaPass

The two fixed post-process steps, each a typed wrapper over FullscreenPass.

Role

TonemapPass runs the ACES filmic curve: it multiplies the HDR buffer by an exposure scalar and writes LDR. FxaaPass runs FXAA edge anti-aliasing over an LDR image (with enabled == false it still runs the pass but the shader passes the source through unchanged). Both are thin: they hold a FullscreenPass, know which generated shader program and uniform block to use, and expose one draw() that takes the source view, a sampler, and the handful of parameters that pass needs.

They exist as their own types so a future renderer can drop tonemapping or FXAA into its own pass chain without re-deriving the pipeline and uniform wiring.

Depends on / depended on by

Depend on FullscreenPass and the generated tonemap / fxaa shader programs (src/graphics/shaders/engine.glsl). Used by DeferredRenderer for its tonemap and FXAA passes.

Public API

class TonemapPass {
    explicit TonemapPass(sg_pixel_format output_format);
    void draw(sg_view hdr, sg_sampler sampler, f32 exposure) const; // pass targeting the LDR attachment must be open
};

class FxaaPass {
    explicit FxaaPass(sg_pixel_format output_format);
    void draw(sg_view source, sg_sampler sampler, int width, int height, bool enabled) const;
};

Worth knowing

  • The shader programs are unchanged from the pre-refactor renderer — same ACES approximation, same FXAA constants, same uniform structs. Only the C++ wrapping moved.
  • Both take an output_format in the constructor and forward it to FullscreenPass::create. In the deferred renderer both are SG_PIXELFORMAT_RGBA8: tonemap writes the m_tonemapped target, FXAA reads that and writes the final m_ldr target. FXAA no longer writes the swapchain directly — the Presenter does the swapchain blit.
