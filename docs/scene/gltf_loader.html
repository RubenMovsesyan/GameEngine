scene::loadGltf

Parses a glTF/glb file with cgltf and returns a populated Scene. The only place in the engine that knows cgltf exists.

Role

Parses the file, walks its node tree accumulating world transforms, and for each node builds either mesh parts (added to a working Model) or a Light (added directly to the Scene). One Model per file, covering every mesh primitive found; every KHR_lights_punctual light found goes into the same Scene.

Depends on / depended on by

Depends on gpu::Device, scene::Scene/Model, graphics::Mesh/Vertex/Light, and cgltf (vendored, single-header). Called directly by test/game code — graphics/ never depends on it or on cgltf; the dependency direction is strictly scene/ → graphics/, never the reverse.

Public API

Scene loadGltf(const gpu::Device&, const std::filesystem::path&);

What it does and doesn't support

  • Triangle primitives only, indexed only — non-indexed or non-triangle primitives are a fatal error, not silently skipped.
  • Requires POSITION, NORMAL, and TEXCOORD_0 on every primitive.
  • Node transforms: cgltf_node_transform_local fills a column-major float[16], which matches Eigen::Matrix4f's default storage directly — Eigen::Map<const Eigen::Matrix4f>(local) reads it with no conversion.
  • Light direction/position come from the owning node's accumulated world transform, not from the light itself — glTF stores punctual lights as node attachments, same as meshes. Direction uses the transform's 3×3 rotation block applied to local (0,0,-1), skipping the inverse-transpose (a simplification, consistent with how mesh normals are handled in gbuffer.vert — correct for uniform scale, not for non-uniform).
  • No materials/textures (nothing exists to attach them to yet), no animation/skinning, no cameras/lights defined outside KHR_lights_punctual.
  • Fatal (not silently degraded) on: parse/buffer-load failure, no default scene, unsupported primitive/light type, missing required attributes — matches the engine-wide convention of RLOG(LL_FATAL, ...) for unrecoverable errors.
