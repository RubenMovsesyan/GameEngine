app::Worker / WorkerBase

A thread that owns some UserData and runs a function of (Application&, UserData&) on it.

Role

WorkerBase is a type-erased handle (pure virtual run()/join()) so Application can hold workers with different UserData types in one std::vector<std::unique_ptr<WorkerBase>>. Worker<UserData> is the concrete templated implementation: it owns the thread, the work function, and the data that function operates on.

Depends on / depended on by

Depends only on the standard library. Owned by app::Application, constructed via its templated addWorker() — see Application.

Public API

class WorkerBase {
    virtual void run() = 0;
    virtual void join() = 0;
};

template <typename UserData>
class Worker : public WorkerBase {
    Worker(Application& app, std::function<void(Application&, UserData&)> work, UserData data);
    void run() override;   // starts the thread
    void join() override;
};

namespace detail {
    template <typename F>
    struct WorkerCallableTraits { using UserData = /* F's 2nd parameter type, decayed */; };
}

Worth knowing

  • The constructor only stores what it needs to run — Application decides when to actually call run(), so a whole batch of workers can be registered before any of them start.
  • WorkerCallableTraits recurses through F::operator() for lambdas/functors, with specializations that stop the recursion for plain function pointers and (non-)const member functions — this is the machinery Application::addWorker uses to infer UserData without it being spelled out at the call site.
