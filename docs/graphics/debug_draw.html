graphics::DebugDraw

Immediate-mode debug lines — AABBs, frustums, axes — drawn as an unlit overlay on top of the finished frame.

Role

A thin wrapper over sokol_gl.h (vendored at external/sokol/util/sokol_gl.h), which does the actual immediate-mode vertex batching and drawing. DebugDraw only adds the world-space, engine-typed API (Eigen vectors, graphics::Frustum corners) on top of it.

Renderer owns one instance and flushes it as the last thing in the frame — inside the same pass FXAA renders into, after FXAA's own draw and the optional shadow-map debug blit, right before sg_end_pass(). That makes debug lines crisp: they are drawn straight to the swapchain, never tonemapped or antialiased, and they render with no depth test, so a line is visible even when it's behind solid geometry. There is currently no depth-tested variant — see below.

Off by default, and a true no-op when off

setEnabled(false) is the constructed state. Every recording method — line(), aabb(), frustum(), axes(), and begin() — starts with if (!m_enabled) return;, so calling them while disabled costs exactly one branch: no sgl_* call happens, nothing is batched, nothing is drawn. render() guards the same way, so Renderer::endFrame() can call begin()/render() unconditionally every frame without its own check, and callers (game code, later engine features) never need an if (debugDrawEnabled) around their own line()/aabb() calls either.

In the sandbox, F3 toggles it: sandbox/model_test/main.cpp calls renderer.debugDraw().setEnabled(!isEnabled()), the same pattern F1/F2 already use for the shadow-map debug blit.

Public API

class DebugDraw {
    DebugDraw();
    ~DebugDraw();

    void setEnabled(bool);
    bool isEnabled() const;

    void line(const Eigen::Vector3f& a, const Eigen::Vector3f& b, const Eigen::Vector4f& color);
    void aabb(const Eigen::AlignedBox3f&, const Eigen::Vector4f& color);
    void frustum(const std::array<Eigen::Vector3f, 8>& corners, const Eigen::Vector4f& color);
    void axes(const Eigen::Matrix4f& transform, f32 scale = 1.0f);

    void begin(const Eigen::Matrix4f& view_projection); // once per frame, before the calls above
    void render();                                        // once per frame, inside an active sg pass
};

Depends on / depended on by

Depends only on the vendored sokol_gl.h — no dependency on gpu::handle.hpp or any other engine GPU wrapper; sgl_context is its own resource type, created and destroyed by sgl_make_context/sgl_destroy_context rather than gpu::makeBuffer/makeImage/etc. graphics::Renderer owns one instance and is the only caller of begin()/render(); anything with a Renderer& can reach it through Renderer::debugDraw() and call the recording methods between beginFrame() and endFrame().

Coordinate spaces

begin(view_projection) sets that matrix as sokol_gl's projection matrix and loads an identity modelview — so every coordinate passed to line()/aabb()/etc. is plain world space, not local space. Eigen::Matrix4f is column-major by default, which is exactly the layout sgl_load_matrix(const float m[16]) expects, so view_projection.data() is passed straight through with no repacking.

Corner ordering

aabb() takes an Eigen::AlignedBox3f and enumerates its 8 corners itself. frustum() instead takes 8 corners directly, in the exact order graphics::Frustum::corners() already produces them: near face {bottom-left, bottom-right, top-left, top-right} at indices 0–3, then the far face in the same bottom-left/bottom-right/top-left/top-right order at indices 4–7. Both build the same 12 line segments — 4 edges around the near/bottom face, 4 around the far/top face, 4 connecting the two — just indexed differently to match each shape's natural corner order.

What isn't here yet

  • Depth-tested lines. A shape occluded by geometry still draws fully visible today. A depth-tested variant needs its own sgl_context built against the HDR target's format (RGBA16F color, D32 depth) and its own pass between the sky pass and tonemap, reading m_depth as a real depth attachment rather than a sampled texture.
  • Wireframe mesh rendering. A separate feature from this one — rendering the actual loaded scene geometry as wireframe triangles has no direct sokol_gfx support (unlike NVRHI's old fillMode = Wireframe raster state); it would need either a barycentric-coordinate discard trick in the G-buffer fragment shader, or a dedicated line-list expansion pass. DebugDraw only draws explicit debug lines, not mesh outlines.
  • Sphere / capsule primitives. Only line()/aabb()/frustum()/axes() exist. A light's range sphere currently has to be approximated with lines by the caller, or added as a new method when a caller actually needs it.
