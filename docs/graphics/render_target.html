graphics::primitives::pass::RenderTarget

An offscreen image plus the two views onto it: one to render through, one to sample afterwards.

Role

Every offscreen buffer a renderer writes and then reads back — the G-buffer attachments, the HDR lighting buffer, the tonemapped and final LDR buffers — is a RenderTarget. It bundles the sg_image with an attachment view (bound as sg_pass.attachments.colors[n] or .depth_stencil) and a texture view (bound into sg_bindings.views[] for a later pass to sample). The two free functions build the common cases so no renderer repeats the three-descriptor dance.

Depends on / depended on by

Depends only on gpu::makeImage / gpu::makeView (src/gpu/handle.hpp) — the shared-ownership handles that destroy the sokol resource when the last holder drops. Used by DeferredRenderer for all its G-buffer, HDR and LDR targets, and available to any future renderer.

Public API

struct RenderTarget {
    gpu::ImageHandle image;
    gpu::ViewHandle  attachment; // render through this
    gpu::ViewHandle  texture;    // sample through this afterwards
};

RenderTarget makeColorTarget(int width, int height, sg_pixel_format format, const char* label);
RenderTarget makeDepthTarget(int width, int height, const char* label); // always SG_PIXELFORMAT_DEPTH

Worth knowing

  • makeDepthTarget creates the depth image with usage.depth_stencil_attachment and a plain texture view, so the deferred lighting and sky passes can sample raw depth back. The pixel format is fixed to SG_PIXELFORMAT_DEPTH — there is no parameter for it because nothing in the engine wants a different depth format.
  • These lived as file-local statics in the old monolithic renderer. They moved out so that any renderer, not just the deferred one, can spin up its own targets without copying the boilerplate.
